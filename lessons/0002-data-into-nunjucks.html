B-Brilliant · Architecture lab · Lesson 02 · About 10 minutes

Data in. HTML out.

Your win: read a render call and a child template, then predict the HTML your browser receives.

This follows the product-request journey: the frontend server has already retrieved and prepared the products. Nunjucks now turns those JavaScript values into HTML. There is no new backend call inside the templates we are studying.

One formula:
template + context + shared layout → generated HTML → browser.

1. The controller hands over named values

Your product controller contains:

const products = await fetchProducts();
res.render('products/index.njk', { products });
  • 'products/index.njk' selects the template under views/. It is a template path, not the browser's URL.
  • { products } is shorthand for { products: products }. It makes a value available under the template name products.
  • The values available to a template are its context. A local JavaScript variable does not become available just because it exists in the controller.

For the examples below, imagine the context is this small object. These are shortened teaching objects, not complete backend product responses:

{
  "products": [
    { "name": "Travel bag", "quantity": 2 },
    { "name": "Mug", "quantity": 0 }
  ]
}

Sources: Express template engines, Nunjucks rendering, and the actual controller.

Where do shared values such as isSignedIn come from?

Middleware in app.ts sets res.locals.isSignedIn, res.locals.csrfToken and res.locals.currentPath. Express makes those values available to templates for that request. The render call supplies page-specific values such as products.

These values are request-scoped; another visitor does not share the same res.locals object. Express: res.locals.

2. Learn three kinds of brackets

Nunjucks syntax mixed into ordinary HTML
SyntaxPurposeExample
{{ ... }}Output a value.{{ product.name }}
{% ... %}Run a template instruction.{% if product.quantity > 0 %}
{# ... #}Leave a template comment; it is not sent in the generated HTML.{# Stock label #}

product.name means “read the name property of this product”. A loop such as {% for product in products %} temporarily names each item product. The singular and plural names are chosen by the author; Nunjucks does not invent the relationship.

A filter changes a value for display: {{ product.name | upper }} displays an uppercase name. It does not update the stored product.

Primary reading: variables, if, for and filters in the official Nunjucks guide.

3. A parent supplies the frame; a child fills its slots

Your real main.njk owns the document, header, menu and shared assets. Its blocks are named places where a child page can supply content.

Shortened parent: main.njk. This sketch omits the real menu and CSS so the block mechanism is easy to see. Do not replace the application template with it.

<!doctype html>
<html lang="en">
<head>
  <title>{% block title %}B-Brilliant{% endblock %}</title>
</head>
<body>
  <header>B-Brilliant</header>
  <main>{% block content %}{% endblock %}</main>
</body>
</html>

Shortened child: products/index.njk. Notice that the child does not repeat <html>, <body> or the header.

{% extends "main.njk" %}

{% block title %}Products | B-Brilliant{% endblock %}

{% block content %}
  <h1>Products</h1>
  <ul>
    {% for product in products %}
      <li>
        {{ product.name }}:
        {% if product.quantity > 0 %}
          In stock
        {% else %}
          Out of stock
        {% endif %}
      </li>
    {% endfor %}
  </ul>
{% endblock %}
  1. extends selects the parent.
  2. The child's title replaces the parent's default title.
  3. The child's content appears inside the parent's <main>.
  4. The loop repeats the list item; the condition chooses the stock text.

Sources: template inheritance and blocks. Compare the sketches with your real product-list template.

4. The browser receives the result, not the instructions

Using the context and two shortened templates above produces this HTML. Blank lines and indentation have been tidied for readability:

<!doctype html>
<html lang="en">
<head>
  <title>Products | B-Brilliant</title>
</head>
<body>
  <header>B-Brilliant</header>
  <main>
    <h1>Products</h1>
    <ul>
      <li>Travel bag: In stock</li>
      <li>Mug: Out of stock</li>
    </ul>
  </main>
</body>
</html>

The Nunjucks extends, for, if and {{ ... }} instructions have been evaluated on the server. They are not browser JavaScript. Changing backend data does not automatically change an already-open page; the data needs to be rendered again or updated by browser code.

Two meanings of “render”: Nunjucks renders a template into HTML on the server. The browser then renders that HTML and CSS into the visible page.

Your app enables autoescape: true. A name such as <b>Bag</b> is escaped when output as a value, so it displays as text rather than becoming a bold HTML element. Do not add | safe merely to make unexpected markup work. Nunjucks configuration.

5. File layout is not visual layout

  • Nunjucks: chooses values, repeated elements, conditional content and shared blocks.
  • HTML: gives the output structure, such as headings, lists, forms and buttons.
  • CSS: controls presentation, such as colours, spacing and side-by-side columns.
  • Indentation: helps a person read the source. It is not a reliable way to add visual spacing in normal HTML.

In the real layout, title supplies the tab title, head allows page-specific head content, content supplies the main page, and scripts allows page-specific scripts. Your product page uses the head block to include product CSS inside a <style> element.

{% include "products/products.css" %} inserts that file's rendered text at that point. include is not the same as extends: one inserts a piece, the other supplies a parent/block layout.

Answer key for printing or use without JavaScript
  1. {{ item.name }}: the context key is item.
  2. Out of stock: the quantity is not greater than zero.
  3. The base template: shared content belongs in the parent.
  4. The CSS rules: presentation is separate from template repetition.
